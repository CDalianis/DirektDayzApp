# Deploy DirectDayzapp online + Android APK

DirectDayzapp can run as:

1. **Online API** on Render (PostgreSQL + Spring Boot Docker service)
2. **Web app** on Render Static Site (browser users)
3. **Android APK** built on your PC, copied to phones via USB (sideload)

The Android app is the same React UI wrapped with **Capacitor**. It calls your **online Render API** — not `localhost`.

```
┌─────────────┐     HTTPS      ┌─────────────────────┐     ┌────────────┐
│ Android APK │ ──────────────►│ directdayzapp-api   │────►│ PostgreSQL │
│ (Capacitor) │                │ (Render Web Service)│     │            │
└─────────────┘                └─────────────────────┘     └────────────┘
       ▲                                ▲
       │ USB copy / adb install         │ Browser
       │                                ▼
   Your PC (build APK)          directdayzapp-web (static site)
```

## Part 1 — Deploy backend + web to Render

### Wrong GitHub repo linked?

**On your PC** (this folder):

```bash
git remote -v                    # see current remote
git remote remove origin       # unlink wrong repo
git remote add origin https://github.com/YOUR_USER/CORRECT_REPO.git
git push -u origin main
```

**On Render:** each service is tied to a repo in **Settings → Build & Deploy → Repository**. Either disconnect and connect the correct repo, or delete the Blueprint/services and create a new Blueprint from the right repo. Render does not follow `git remote` on your machine — you fix it in the [Render Dashboard](https://dashboard.render.com).

**On GitHub:** you can delete or archive the mistaken repo (`Direktdzapp`) if you no longer need it.

---

### 1. Push to GitHub

```bash
git init
git add .
git commit -m "DirectDayzapp"
git remote add origin https://github.com/YOUR_USER/directdayzapp.git
git push -u origin main
```

### 2. Create Render Blueprint

In [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint** → connect the repo.

`render.yaml` creates:

| Resource | Name | Type |
|----------|------|------|
| Database | `directdayzapp-db` | PostgreSQL (free) |
| API | `directdayzapp-api` | Docker / Spring Boot |
| Web | `directdayzapp-web` | Static site (Vite build) |

### 3. First deploy — API environment

Render auto-links Postgres and sets `SPRING_DATASOURCE_*`. After the first deploy, open **directdayzapp-api** → **Environment** and verify:

| Variable | Value |
|----------|--------|
| `ALLOWED_ORIGINS` | `https://directdayzapp-web.onrender.com,https://localhost,capacitor://localhost` |
| `APP_SECURITY_SECRET_KEY` | Auto-generated by blueprint (or set a long random Base64 string) |
| `LOG_LEVEL` | `INFO` (default) |

Note your API URL: **`https://directdayzapp-api.onrender.com`**

**Health check:** `https://directdayzapp-api.onrender.com/v3/api-docs` should return JSON.

**Swagger:** `https://directdayzapp-api.onrender.com/swagger-ui/index.html`

### 4. Configure the static web site

Open **directdayzapp-web** → **Environment** → add:

```env
VITE_API_URL=https://directdayzapp-api.onrender.com/api/v1
```

Replace the host if you renamed the API service. **Redeploy** the static site so Vite bakes the URL into the build.

Browser URL: **`https://directdayzapp-web.onrender.com`**

### 5. Database migrations

Flyway runs automatically when the API starts. Current migrations:

- `V1__schema.sql` — schema
- `V2__seed_data.sql` — roles, capabilities, seed regions
- `V3__add_greek_regions.sql` — **13 Greek peripheries** (replaces legacy “Macedonia”)

After each deploy, check API logs for `Successfully applied migration` or `Schema is up to date`.

**Existing DB before V3:** producers on the old “Macedonia” region are moved to **Central Macedonia**.

### 6. Verify production

- [ ] `GET https://directdayzapp-api.onrender.com/api/v1/regions` returns **13** regions  
- [ ] Web home page loads the Greece map; clicking a region filters products  
- [ ] EN / ΕΛ language toggle works  
- [ ] Register producer → region dropdown lists all peripheries

## Part 2 — Build the Android APK (on your PC)

### Prerequisites (one-time)

1. [Android Studio](https://developer.android.com/studio) (JDK + Android SDK)
2. Node.js 20+
3. Open Android Studio once and finish the SDK setup wizard

### 1. Point the app at your live API

```bash
cd honeyapp-frontend
cp .env.production.example .env.production
```

Edit `.env.production`:

```env
VITE_API_URL=https://directdayzapp-api.onrender.com/api/v1
```

Use your real Render API URL. This file is used by `vite build` for mobile/production.

### 2. Android SDK path

Copy the example and set your SDK location:

```bash
cp android/local.properties.example android/local.properties
```

Edit `sdk.dir` (Windows example):

```properties
sdk.dir=C\:\\Users\\YOUR_USER\\AppData\\Local\\Android\\Sdk
```

Do **not** commit `local.properties`.

### 3. Build web assets and sync to Android

```bash
npm install
npm run build:mobile
```

Runs `tsc`, `vite build`, and `cap sync android`.

### 4. Build the APK

The `.apk` appears only **after Gradle runs**, at:

```
honeyapp-frontend/android/app/build/outputs/apk/debug/app-debug.apk
```

**Option A — npm script (Windows)**

```bash
npm run build:apk
```

**Option B — Android Studio**

```bash
npm run cap:open
```

**Build → Build Bundle(s) / APK(s) → Build APK(s)**

**Option C — Gradle directly**

```bash
cd android
gradlew.bat assembleDebug        # Windows
./gradlew assembleDebug          # Linux / macOS
```

The installed app name on the phone is **DirectDayzapp** (`com.directdayzapp.mobile`).

### 5. Copy APK for easy sharing (optional)

```bash
cp android/app/build/outputs/apk/debug/app-debug.apk ~/Downloads/DirectDayzapp.apk
```

## Part 3 — Install APK on phones via USB

### Method A — Copy file (no adb)

1. Connect phone to PC (USB)
2. On phone: **File transfer / MTP**
3. Copy `app-debug.apk` to **Downloads**
4. Open **Files** on the phone → tap the APK
5. Allow **Install unknown apps** for your file manager if prompted
6. Tap **Install**

### Method B — adb

1. **Settings → About phone** → tap **Build number** 7 times  
2. **Developer options** → **USB debugging** on  
3. Connect USB, accept the debugging prompt  
4. On PC (SDK platform-tools in PATH):

```bash
adb install honeyapp-frontend/android/app/build/outputs/apk/debug/app-debug.apk
```

## Updating after code changes

### API / database

Push to GitHub → Render redeploys **directdayzapp-api** → Flyway applies new migrations.

### Web

Push → Render rebuilds **directdayzapp-web** (ensure `VITE_API_URL` is still correct).

### APK

1. Update `.env.production` if the API URL changed  
2. `npm run build:apk`  
3. Distribute the new APK via USB (users reinstall)

For smoother updates later, set up release signing and increment `versionCode` in `android/app/build.gradle`.

## Environment reference

### Render — `directdayzapp-api`

| Variable | Required | Notes |
|----------|----------|-------|
| `SPRING_DATASOURCE_URL` | Yes | From linked Postgres |
| `SPRING_DATASOURCE_USERNAME` | Yes | From linked Postgres |
| `SPRING_DATASOURCE_PASSWORD` | Yes | From linked Postgres |
| `APP_SECURITY_SECRET_KEY` | Yes | JWT secret (Base64) |
| `ALLOWED_ORIGINS` | Yes | Web + Capacitor origins |
| `PORT` | Auto | Set by Render |
| `FILE_UPLOAD_DIR` | Optional | Default `./uploads/` (ephemeral on free tier) |
| `LOG_LEVEL` | Optional | Default `INFO` |

### Render — `directdayzapp-web`

| Variable | Required | Notes |
|----------|----------|-------|
| `VITE_API_URL` | Yes | e.g. `https://directdayzapp-api.onrender.com/api/v1` |

### Local — `honeyapp-frontend/.env`

```env
VITE_API_URL=http://localhost:8080/api/v1
```

### Local — backend (defaults in `application.yml`)

Uses `jdbc:postgresql://localhost:5432/directdayzapp` with user/password `directdayzapp` when env vars are unset.

## Important notes

| Topic | Detail |
|-------|--------|
| **Free tier sleep** | Render free services spin down after ~15 min idle. First request may take 30–60s. |
| **HTTPS** | Render uses HTTPS. Capacitor is configured with `androidScheme: https`. |
| **CORS** | `ALLOWED_ORIGINS` must include `https://localhost` and `capacitor://localhost` for the Android WebView. |
| **File uploads** | Certification files use server disk — **ephemeral** on Render free tier. Use S3/R2 for production. |
| **Play Store** | This guide is for **private sideloading**. Play Store needs signed release builds + privacy policy. |
| **Map data** | Greece map uses Simplemaps admin-1 SVG; attribution is shown in the app. |
| **Region names** | API filters use exact English periphery names, e.g. `?region=Central%20Macedonia`. |

## Troubleshooting

| Problem | Fix |
|---------|-----|
| API 502 / slow first load | Free tier waking up — wait and retry |
| CORS errors in browser | Add your web URL to `ALLOWED_ORIGINS` on the API |
| APK shows blank / network errors | Rebuild with correct `VITE_API_URL` in `.env.production` |
| `SDK location not found` | Create `android/local.properties` with `sdk.dir=...` |
| Gradle fails on Windows | Run from `android/` with `gradlew.bat`, not `gradle` |
| Regions missing / only 6 | Restart API so Flyway runs `V3__add_greek_regions.sql` |
| `?region=Macedonia` empty | Legacy name removed — use `Central Macedonia`, `Western Macedonia`, or `Eastern Macedonia and Thrace` |
